The problem

        
A safety test is only as good as its isolation.

        
Red team, blue team and the client model share one sandbox. Any leak between them quietly invalidates the findings, and today nobody can prove afterwards that the test was fair.

        

          
Blue sees the attacks
If defenders glimpse attack payloads early, the defence looks stronger than it is.

          
Shared caches talk
On shared model servers, one tenant can infer another's prompt from response timing (NDSS 2025).

          
Logs can be rewritten
Without tamper-evident records, results can be edited after the fact and nobody would know.

        

      

    


    

      

        
How Bayora works

        
Five mechanisms, one verifiable protocol.

        
The building blocks are established. Bayora's contribution is combining them into a single evaluation that ends in evidence a third party can check.

        

          
01
Blind commitments
Both teams commit a hash of payloads and rules before the run; contents are revealed and checked after.

          
02
Enforced zones
Separate containers per team, a broker as the only path, and an eBPF policy that denies everything else.

          
03
Attributed canaries
Key-derived tripwires name who leaked, through which channel. Leak drills measure the catch rate.

          
04
Salted serving
Per-tenant cache salt blocks prefix reuse, and a timing attack runs before every evaluation to prove it.

          
05
Witnessed receipt
A Merkle log co-signed by independent witnesses, ending in a signed in-toto receipt anyone can verify.
